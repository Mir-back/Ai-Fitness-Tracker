# Техническое задание — Forme Fitness

## 1. Общие сведения

**Название:** Forme Fitness — AI Fitness Tracker.  
**Назначение:** учебный веб‑проект для промежуточного экзамена по дисциплине Programming Language.  
**Цель:** предоставить пользователю единое место для фиксации физической активности, наблюдения за регулярностью и получения персональных рекомендаций для следующего занятия.

## 2. Пользователи и сценарии

Основной пользователь — человек, который хочет начать тренироваться или поддерживать существующий режим. После открытия сайта он может посмотреть демо, зарегистрироваться или войти, указать цель и опыт, записать тренировку, просмотреть историю и получить рекомендацию.

### Основной сценарий

1. Пользователь открывает сайт и регистрирует аккаунт либо выбирает демонстрационный режим.
2. Указывает имя, цель тренировок, опыт, доступное оборудование и количество тренировочных дней в неделю.
3. Открывает обзор с текущей статистикой и рекомендацией следующего занятия.
4. Добавляет тренировку с названием, типом активности, длительностью, уровнем нагрузки и необязательной заметкой.
5. Просматривает журнал, недельный график и серию последовательных тренировочных дней.
6. Обновляет профиль; рекомендации пересчитываются с учётом профиля и истории.

## 3. Функциональные требования

### Аккаунт и профиль

- Регистрация по account ID или адресу электронной почты и паролю длиной от 8 символов.
- Вход и выход; сервер хранит хеш пароля, а клиент — токен сессии.
- Профиль содержит имя, цель (`consistency`, `strength`, `endurance`, `mobility`, `weight`), опыт (`beginner`, `intermediate`, `advanced`), оборудование и цель в 2–6 тренировок в неделю.
- Демонстрационный режим позволяет ознакомиться с интерфейсом без регистрации.

### Тренировки и статистика

- Создание записи с названием длиной 2–70 символов, типом активности, длительностью 1–300 минут, субъективной нагрузкой 1–5 и заметкой до 240 символов.
- Просмотр списка записей по дате и удаление тренировки.
- Расчёт количества тренировок и минут за текущую неделю, недельного прогресса, семидневной активности и серии тренировочных дней.
- Пустые состояния объясняют, как добавить первую запись.

### Персональные рекомендации

- Рекомендация формируется серверным модулем правил по цели, опыту, оборудованию, дате последнего занятия и истории активности.
- Предложение включает тип, длительность и пояснение с безопасным напоминанием остановиться при боли.
- Если пользователь уже тренировался сегодня, сайт предлагает восстановление. После длительного перерыва — облегчённое возвращение.
- Рекомендации предназначены для учебного проекта и не являются медицинским советом.

## 4. Интерфейс и доступность

- Адаптивная панель обзора с навигацией, карточками статистики, графиком и списком последних тренировок.
- Разделы: Overview, Workouts, AI Coach; диалоги регистрации, записи занятия и профиля.
- Поддержка клавиатурного закрытия диалогов (Escape), подписанные формы и сообщение о состоянии отправки.
- Мобильная навигация и адаптация сеток для узкого экрана.
- Визуальный язык согласован с MealMate: графитовый фон, лаймовый акцент, шрифты Space Grotesk и DM Sans, округлые карточки, editorial‑типографика и абстрактная графика. Тексты, бренд и предметные элементы разработаны для фитнес‑проекта.

## 5. Техническая архитектура

- Клиент: HTML5, CSS3, JavaScript без фреймворков и сборщика.
- Сервер: Node.js 18+, встроенный модуль `http`, JSON REST API.
- Хранение: локальный JSON‑файл `data/fitness-data.json`; файл исключён из Git.
- API: `POST /api/register`, `POST /api/login`, `POST /api/demo`, `POST /api/logout`, `GET /api/me`, `GET /api/recommendations`, `PUT /api/profile`, `POST /api/workouts`, `DELETE /api/workouts/:id`.
- Сервер проверяет размеры запросов, допустимые диапазоны полей и сессию пользователя. Пароли хешируются `scrypt` с индивидуальной случайной солью.
- При публикации на GitHub Pages данные демо сохраняются в браузере; Pages не исполняет Node.js. Серверный режим доступен при запуске Node.js‑сервера.

## 6. Нефункциональные требования

- Запуск на Windows, macOS и Linux при установленном Node.js 18+.
- Не требуется установка npm‑зависимостей, база данных или внешний API‑ключ.
- Основные экраны должны оставаться пригодными для использования на мобильном экране от 320 px шириной.
- Данные локального сервера сохраняются после его перезапуска.

## 7. Критерии приёмки

1. Команда `start.ps1` (Windows) или `start.sh` (macOS/Linux) запускает сайт по адресу `http://localhost:4173/`.
2. Посетитель может открыть демо либо зарегистрироваться и повторно войти с созданными учётными данными.
3. Профиль можно сохранить и изменить.
4. Добавленная тренировка отображается в списке, истории и статистике; её можно удалить.
5. Карточка AI Coach показывает персональную рекомендацию и недельный ориентир.
6. Обновление страницы не теряет серверные записи; в статическом демо записи сохраняются в браузере.
7. Основные действия доступны на настольном и мобильном размерах экрана.

## 8. Границы прототипа

Алгоритм рекомендаций основан на правилах, а не на подключённой генеративной модели. Файл JSON рассчитан на учебную демонстрацию и локальную работу, не на многопользовательскую производственную нагрузку. Демо‑режим Pages хранит данные только в браузере и не синхронизирует их между устройствами.
